# addPermission

Registers a permission group that defines which endpoints are covered by a named permission. Permission keys are referenced in controller `permission.items` arrays and resolve to `@PreAuthorize` expressions.

## Schema

```typescript
interface PermissionConfig {
  type: 'permission';       // required, literal
  name: string;             // required, permission group name
  description: string;      // required
  endpoints: IEndpoint[];   // required, non-empty
}

interface IEndpoint {
  type: 'controller' | 'model'; // required
  resource: string;              // required, controller or model name
  method: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE'; // required
  path: string;                  // required, full endpoint URL path
}
```

## Manifest Output

Written to: `.igrpstudio/permissions/<PermissionName>.json`

## Related Operations

| Function | Effect |
|---|---|
| `addPermission(config, basePath)` | Saves `.igrpstudio/permissions/<Name>.json` |
| `deletePermission(config, basePath)` | Removes `.igrpstudio/permissions/<Name>.json` |
| `getPermissions(basePath)` | Loads all manifests from `.igrpstudio/permissions/` |

## How Permissions Connect to Controllers

The permission config is **metadata only** — it does not generate Java code directly. The `@PreAuthorize` annotation is generated by `addController` when actions have a `permission` field:

```json
"permission": { "items": ["ORDERS_WRITE"], "operator": "OR" }
```
↓ generates:
```java
@PreAuthorize("hasAuthority('ORDERS_WRITE')")
```

The permission manifest records the human-readable group name, description, and which endpoints it governs. iGRP Studio uses this metadata to manage permission assignments in the UI.

## Example

```json
{
  "type": "permission",
  "name": "OrdersManagement",
  "description": "Permissions for managing order resources",
  "endpoints": [
    {
      "type": "controller",
      "resource": "Order",
      "method": "GET",
      "path": "/api/v1/orders"
    },
    {
      "type": "controller",
      "resource": "Order",
      "method": "POST",
      "path": "/api/v1/orders"
    },
    {
      "type": "controller",
      "resource": "Order",
      "method": "DELETE",
      "path": "/api/v1/orders/{id}"
    }
  ]
}
```

## Notes

- Use `getPermissions()` to inspect all current permission definitions before adding new ones — avoid duplicate names.
- When `deleteElement` removes a controller, its permission endpoints are automatically removed from all permission manifests.
- When `deleteElement` removes a model with `crud: true`, its CRUD endpoints are also cleaned from permission manifests.
